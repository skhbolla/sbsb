## intro

- The Problem & Solution: Tight coupling between applications is bad for cloud systems at scale. We need to decouple the communication between components, and EventBridge is the AWS-managed service that provides this exact benefit. [6, 7, 8, 9]
- The Mesh Architecture: It acts as an event mesh where event notifications are written to a bus. Rules are then utilized to check if any service is listening for this specific notification. If no rules match, the event is simply discarded (unless an Archive is enabled on the bus to save historical data). If a rule does match, the notification is forwarded to the listening target. [10, 11, 12, 13, 14]
- The Bus Types: These notifications are pushed to the Default Bus automatically by almost all AWS services out of the box, but we can also custom-push our own application data to the bus. Additionally, we can create Custom Buses to isolate our traffic, or use Partner Event Buses pre-created for third-party integrations (like Auth0 or Datadog). [15, 16, 17, 18, 19]
- The Filtering Logic: Content Filtering refers to the declarative JSON-matching schemas we define directly inside those rules to handle line-rate pattern matching.
- The Sculpting Layer: Sometimes the raw input payload needs to be transformed into a completely different shape for the target to utilize it. This is where Input Transformation comes in, reshaping the JSON payload natively without needing an extra Lambda function.
- Point-to-Point Routing: While the Event Bus is built for many-to-many topographies, we can use EventBridge Pipes for strict point-to-point integrations. Pipes give us a managed 4-stage assembly line to Source from a stream or queue, Filter out junk, Enrich data via external APIs, and ship it to a final Target. [20, 21, 22]
- The Safety Net (Added): Finally, if a target is down or rate-limited during delivery, EventBridge runs a managed Retry Policy with exponential backoff for up to 24 hours. If it still fails after 24 hours, EventBridge routes the raw message and its diagnostic error attributes into an SQS Dead Letter Queue (DLQ) to prevent data loss. [23, 24, 25]
